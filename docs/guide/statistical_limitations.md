# 置信度、效力与统计局限

## 三类数字必须区分

1. **全量描述量**：在实际扫描范围内精确统计，例如字符数或 exact hash 命中率。它仍受
   指标定义和实现误差约束，但没有抽样误差。
2. **样本估计量**：从随机样本推断总体比例，需要报告样本量、抽样框、seed 和区间。
3. **检测器命中率**：模型或规则输出阳性的比例，同时包含真阳、假阳和漏检，不能自动
   解释为真实风险率。

## 抽样前提

默认蓄水池抽样只在输入迭代器完整遍历且每条记录只出现一次时提供等概率样本。若先限定
文件、只扫描部分 shard、读取中途失败或使用 `head`，样本就不代表整个数据集。分 shard
采固定条数会让小 shard 过度代表，除非按 shard 大小加权。

对于总体比例 `p`，简单随机样本可报告 Wilson 95% 区间。零命中时不要写“风险率为 0”；
粗略的 rule of three 给出 95% 上界约 `3/n`，例如 5,000 条零命中的上界约为 0.06%。
存在 cluster、来源或模板相关性时，有效样本量低于记录数，普通二项区间会过窄，应按 shard
或来源做分层/cluster bootstrap。

## 低频风险的检出效力

若真实发生率为 `p`，随机抽样 `n` 条至少命中一次的概率是 `1-(1-p)^n`。因此：

| 假设真实发生率 | 约 95% 概率至少命中一次所需样本 |
|---:|---:|
| 1% | 299 |
| 0.1% | 2,995 |
| 0.01% | 29,956 |
| 0.001% | 299,572 |

这只是抽到风险样本的效力，尚未考虑检测器 recall。检测器 recall 为 50% 时，有效发生率
还要再减半。

## 检测器效力

PII、toxicity、语义重复、污染和合成检测必须使用与目标语言/领域接近的标注集或注入真值集
估计 precision、recall 和阈值敏感性。只有“正负数据集方向符合预期”可以证明一定区分度，
不能证明漏检率。人工抽检必须记录：抽样方式、标注准则、标注人数、分歧处理和有效样本量。

LLM Judge 的 `confidence` 是模型自报分数，不是统计校准概率。需要独立人工集验证可靠性，
模型或 prompt 变化后重新校准。

## 多重比较与阈值

本项目同时输出多个指标、语言、来源和 flag。只挑最异常的结果会放大偶然波动。正式报告
应预先指定主指标，次要指标标为探索性；跨多个数据集比较时保持同一配置，或明确说明参数
变化。基于一个数据集调出的红绿灯阈值不能直接用于另一个分布。

## 报告最低要求

每个结论至少附带：

- 总体和实际扫描范围；
- 全量或抽样、抽样方法、seed、样本量和 shard 覆盖；
- 指标/模型/tokenizer 版本与阈值；
- 点估计及适用的区间或多 seed 范围；
- 已知 precision/recall，未知时明确写“未知”；
- 失败 shard、截断、unsupported 和人工复核数量；
- 硬件、耗时和代码 commit。

缺少上述信息的结果可用于探索，不应作为发布门槛或清洗决策的唯一依据。
